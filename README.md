# hxwl-01 听力验配记录 · 可续作的验配链

门店听力师在**断网复诊**场景下的验配合并工作台：把「验配记录（修订）」「复诊预约」「试听设备台账」三条记录接成一条可续作、可回滚、可追查的链。

## 解决什么问题

门店复诊断网时，听力师离线修订回连后容易和验配记录、复诊预约、试听设备台账**各改各的**，旧结论还会继续占机、排诊。本工作台的规则：

1. **修订按序号合并，冲突全留待确认**
   - 修订只记录“改了哪些字段”，带修订序号、工位、所依据的结论版本（乐观锁）；断网时进工位发件箱持久化（刷新不丢），回连后接回。
   - 离线并发撞号不改号，按 `(序号, 时间, 工位)` 排序；同一字段不同值全部保留为候选并标冲突。
   - **未确认的修订绝不覆盖当前有效结论**；冲突字段必须由主管逐字段裁决并写明理由。
2. **有效结论变化 → 下游失效重算**
   - 主管确认产生只追加的新版本；尚未执行的预约与设备预占一律作废（预约 invalidated、预占红冲 RELEASE 流水），按新结论重排；**已执行的预约/已兑现预占不动**。
3. **容量不足按可兑现分批，写入失败整批恢复**
   - 按复诊日期切“完整批次”：可兑现才整批写入台账（RESERVE 流水 + 预约占机）；容量不足预约保留为 `waiting`，不占机、不让旧结论继续排诊，补库存（INBOUND 流水）后可重排。
   - 台账写入故障在写入前拦截：失败批次不留任何占用，批次回滚、预约回 waiting，前序已兑现批次不受影响，故障消除后从完整批次边界重试续作。
4. **全程留痕，不是“只负责保存的一张表”**
   - 旧版本结论、旧修订（confirmed / superseded 都保留）、主管裁决理由（变更依据随版本归档）、库存流水（只追加，含当日结余）、验配链事件流（连续序号）均可追查。

## 模块结构

```
src/domain/
  types.ts         # 修订/合并提案/结论版本/预约/预占/批次/流水/事件 模型
  errors.ts        # 领域错误 + 台账写入故障
  storage.ts       # 仓储：持久化、整批原子写入、故障注入
  chain.ts         # ChainService：合并/确认/失效重算/分批回滚/重排/审计
  seed.ts          # 可复现演示场景（两工位 + 容量受限台账）
  domain.test.ts   # 6 组场景 / 53 条断言（零依赖，node 直接跑）
src/ui/            # 修订台 / 主管确认台 / 下游预约设备面板 / 追查审计面板
src/state/         # React 接线（断网本地续作）
```

## 运行

```bash
npm install
npm run dev      # 工作台 http://localhost:5101
npm test         # 领域规则自检（6 场景 53 断言）
npm run build    # tsc 严格类型检查 + vite 构建
```

## 界面演练路线

1. 两个工位分别「模拟断网」，两位听力师各改一版增益（序号撞车）；
2. 各自「回连同步」→ 主管确认台出现两个增益候选，冲突字段要求裁决；
3. 主管选定候选、填写裁决依据后确认 → 现行结论升级 v2，旧复诊失效、旧预占释放、新预约按新机型重算占机；
4. 「注入台账写入故障」后再改一版结论，观察整批回滚、预约 waiting，再点「重试」从完整批次恢复；
5. 底部追查面板查看事件链、旧修订归档、结论版本 + 变更依据、库存流水。
