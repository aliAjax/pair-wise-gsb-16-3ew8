# hxwl-01 听力验配记录 · 可续作的验配链

门店听力师断网复诊时，验配记录、复诊预约、试听设备台账不能各改各的。
本项目把三者接成一条会联动、可续作、可追查的链，而不是只负责保存的一张表。

## 技术栈

React + Vite + TypeScript + CSS，零额外运行时依赖；测试基于内置 `node:test` + esbuild。

## 本地运行

```bash
npm install
npm run dev       # http://localhost:5101
npm test          # 领域规则测试（13 个）
npm run build     # tsc 类型检查 + 生产构建
```

## 链路规则（`src/domain/`）

### 1. 验配记录：修订序号合并，冲突全留待确认（`fittingRecord.ts`）

- 听力师断网修订记录 `baseSeq`（所基于的序号）、`clientId` 幂等键和变更依据；
- 回连后按**记录内单调修订序号**合并，同一 `clientId` 重复推送不重复占号；
- 同字段两人改出不同值时走三方合并，**所有取值都留作候选**，当前有效值也在候选中（主管可维持旧结论）；
- 待确认批次存在未裁决冲突时禁止放行——**未确认的修订不能覆盖当前有效结论**，旧结论继续占机排诊；
- 主管逐字段裁决、整批确认，有效结论版本 `version +1`；旧修订**归档而非删除**。

### 2. 有效结论变化 → 预约与预占失效重算（`chain.ts` / `scheduler.ts`）

主管确认且结论字段实际变化后，链路自动执行：

1. 该患者所有**未执行**复诊预约失效、试听设备预占释放（留审计，不静默删除）；
2. 按新结论重建复诊请求（含新机型），结合诊位与设备容量重算；
3. 按优先级把**可兑现**的请求组成一个完整批次，容量不足者顺延；
4. 整批原子提交：任一步写入失败 → 按提交前快照恢复库存/预占/预约，请求回到顺延队列，可原样重试。

### 3. 试听设备台账（`deviceLedger.ts`）

- 库存只通过只增流水变动：入库 / 出库 / 预占 / 释放；
- 容量按“型号 + 日期”计算：当日可试听 = 在店 − 当日已预占。

### 4. 可追查（`audit.ts`）

一条只增时间线串起：建档、修订合并/冲突、主管确认与变更依据、预约失效/重排/顺延、
设备 reserve/release 流水、批次回滚。支持按患者过滤；旧修订（含 seq/baseSeq/批次/依据）归档可查。

## 演示现场（`src/demo.ts` + 工作台 UI）

开机即处于真实现场：刘阿姨 v1 已占 10-08 的 RIC-200（当日仅 1 台），陈大爷同日需求顺延。
操作路径：**① 模拟两人断网复诊 → ② 回连提交修订 → ③ 主管裁决冲突并确认联动重排**，
还可勾选“模拟设备写入失败”观察整批回滚与重试、调拨入库后兑现顺延预约，右侧时间线全程可追查。

## 目录

```
src/domain/
  types.ts            领域类型与字段词表
  fittingRecord.ts    修订序号 / 三方合并 / 冲突候选 / 确认放行
  scheduler.ts        失效重算 / 容量分批 / 快照事务提交
  deviceLedger.ts     容量与只增库存流水
  audit.ts            只增审计时间线（支持事务暂存）
  chain.ts            三者联动的门面
  *.test.ts           规则测试
src/App.tsx           联动工作台
src/demo.ts           演示现场引导
```
